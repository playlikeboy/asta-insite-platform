# Migration Guide

Migrations are generated by Drizzle Kit and committed in `packages/database/migrations`.

## Change the schema

```bash
# 1. Edit packages/database/src/schema/index.ts
pnpm db:generate             # 2. Writes SQL and metadata
# 3. Read the generated SQL
TEST_DATABASE_URL=... pnpm --filter @asta/database test   # 4. Tests apply all migrations from empty
# 5. Commit schema and migration together
```

CI fails if `pnpm db:generate` produces a change that was not committed.

## Apply

Migrations use the **direct** URL on port 5432. The pooler cannot run them.

```bash
DIRECT_URL=postgresql://...:5432/... pnpm db:migrate
```

Order per environment: dev, then staging, then a branch rehearsal of production, then production.

## Rules

- Never edit a migration that has been applied anywhere shared. Add a new one.
- Never use `drizzle-kit push` on staging or production.
- Take a manual backup before a risky production migration.
- Add indexes to large tables with `CREATE INDEX CONCURRENTLY` in a hand-written migration outside a transaction.

## Expand, then contract

Old mobile apps stay in use, so breaking changes take several releases:

1. **Expand:** add the new column or table, nullable or with a default.
2. **Migrate code:** write both; read new. Release API.
3. **Backfill** in small batches.
4. **Contract:** drop the old column only after no supported app version needs it.

## Rollback

Drizzle generates forward migrations only. To undo, write a new forward migration. If data was damaged, restore from a backup or point-in-time recovery; see [Backup and restore](../operations/BACKUP_AND_RESTORE.md).

## Rehearsal

Appwrite database branches create isolated copies with their own connection strings. Create a branch, run the migration, run tests, delete the branch.
